## [1.1.0] — Unreleased

### Behaviour changes (read before upgrading)

- **Relaxations now need a code only you see.** After the upgrade, each unexpired 1.0 grant becomes a pending request: confirm each with the code shown at your first 1.1.0 session, or re-create it. (A 1.0 `autopilot` mode becomes the `relaxed` tier; see the next item.) The 1.0 spend ledger counts as spent for the rest of that UTC day. Headless `claude -p` can't confirm anything.
- **Tiers replace profiles.** The firewall takes a tier as an input: `off < relaxed < medium < high`, default `relaxed` (the full table is in the README and `docs/tiers.md`). `strict` becomes `relaxed`, `paranoid` becomes `high`, and `autopilot` becomes `relaxed` (the notice names `safe-ai-skill allow --scope transfer`). A 1.0 `off` is set aside with a hint, never migrated; the first session prints one line about the migration. Choose a tier with `safe-ai-skill tier [<name>] [--project] [--env-read deny|ask|tier]` (`mode` stays as a deprecated alias). **Only a user-scope, authenticated `tier.json` can lower a tier**, and a lowering waits for your whole-prompt `safe-ai-skill confirm <code>`. solana-ai-kit's `.claude/security.json` (`tier`, `declared.tier`, `enforced.tier`), a repo's `.safe-ai-skill/policy.yaml` `tier` and `SAFE_AI_SKILL_TIER` (alias `SAFE_AI_SKILL_PROFILE`) can only raise it, and each ignored lower hint is noted at SessionStart. **The tier `off` is not `SAFE_AI_SKILL_DISABLE=1`:** every `deny` row of the tier table holds at Off.
- **Irreversible actions (Class U) deny on mainnet and unidentified clusters.** `--final` deploys and upgrades, `program-v4 finalize`, `program close`, `spl-token close-mint|close|burn`, `authorize --disable`, `anchor idl erase-authority|close` and `close-vote-account` deny on mainnet, testnet and any cluster that isn't positively identified as localnet or devnet (an unreadable `-C` file, `$URL`, no config), and ask on an identified localnet or devnet. A grant, a tier, a repo setting or an env variable never relaxes either verdict. In 1.0.1 these asked on every cluster and only a mainnet `--final` denied. Overwriting, deleting or `--force`-regenerating the default wallet denies on every cluster.
- **Class C on mainnet or Unknown denies at High**; a grant never allows at High, and the engine never emits `allow` at High. A transfer within the spend caps on an identified test cluster is no opinion at High.
- **An inline `curl`/`wget` POST body no longer asks below High** (JSON-RPC calls to a devnet RPC included). It still asks at High. CI runs that the 1.0.1 ask would have failed under `claude -p` now pass at Relaxed.
- **Headless runs turn every `ask` into a `deny`.** Headless is on when `SAFE_AI_SKILL_HEADLESS` or `KIT_FIREWALL_HEADLESS` is `1`/`true`, a CI variable (`CI`, `GITHUB_ACTIONS`, `GITLAB_CI`, `BUILDKITE`, `JENKINS_URL`) is set and not `0`/`false`, or `/dev/tty` can't be opened; nothing turns it off. Only a grant you confirmed interactively beforehand passes (below High). `CONFIRM_MAINNET`-style env escapes are ignored.
- **Home credential stores are read-denied at every tier**, through Read, Grep, MCP path arguments, Bash readers and command forms (`gh auth token`, `git credential fill`, `security find-generic-password -w`, `aws configure get *secret*`, `npm config get *_authToken`, `docker-credential-* get`, `secret-tool lookup`, `pass show`, `op read`, `bw get`): `~/.ssh/**` (except `config`, `known_hosts`, `*.pub`, which are now readable), `~/.gnupg`, `~/.aws`, `~/.kube/config`, registry and git-host tokens, keychains and password managers, browser profiles and wallet-extension data. A directory Grep rooted at or above `$HOME` gets every credential glob appended, which closes the 1.0.1 limitation where a directory-wide Grep could return `.env*` contents.
- **Naive-exfil tripwire (best-effort).** A network-capable command (curl, wget, nc, scp, `git push`/`remote add`, an interpreter one-liner naming a URL, …) that takes a secret file as input is denied (key material at every tier, project env files from Relaxed), and so is a request to a known exfil host (70/79/84 hosts at Relaxed/Medium/High; none at Off). It does not stop IP literals, redirects, DNS, unlisted hosts or values already in context.
- **Project `.env`: the default stays deny.** An opt-in raw read is `safe-ai-skill tier --env-read ask|tier`, user scope only, and works only while the sandbox is declared on (a supported platform). Write, Edit and MultiEdit to a project env file, and an agent-run `env set|unset`, are denied at Medium and High. The `secrets.env_read` key of the plugin policy is replaced by it. Writes through Bash (`sed -i`, `perl -pi`, `python3 -c`) are not covered at any tier.
- **Supply chain follows the tier.** Combination BLOCKs, drift, `lock_mismatch` and unscanned packs are reported at Off and denied in place from Relaxed; a HIGH heuristic (unreviewed) is denied only at High, until `verify trust` or `approve`. A repo `packs.lock` can't clear it. Nothing is moved by default at any tier; `on_block: move` never touches a git-tracked pack or submodule path.
- **Shared lists.** The credential globs, exfil hosts and on-chain verbs live in `policy/shared/` (a `MANIFEST` with a sha256 per file), seeded from solana-ai-kit's `firewall.sh` at `42755ab` and embedded in the engine at build. A list that fails to parse at runtime makes its gates fall back to a hard-guard `ask`. You can add hosts and key-material globs (`secrets.exfil_hosts_extra`, `secrets.key_material_extra_globs`); nothing removes an entry.
- **Skill packs: drift is a BLOCK, not a warning.** A pinned pack whose content changes is denied (Skill tool, `/name`, reads and Bash access inside it) until you run `safe-ai-skill verify approve <name>` in a terminal and confirm it. Packs are never moved unless `supply_chain.on_block: move`. A pack the SessionStart sweep could not fully scan in its time budget is denied the same way until a later sweep scans it.
- **The agent can't read Claude Code transcripts or the state key.** Reads of `~/.claude/projects/**` (and `$CLAUDE_CONFIG_DIR/projects`) and of `<data dir>/key` are denied, through Read, Grep and Bash.
- **The CLI needs an installed plugin.** From a terminal it uses `$CLAUDE_PLUGIN_DATA`, else the plugin's dir under `$CLAUDE_CONFIG_DIR/plugins/data` (which replaces `~/.claude`) or `~/.claude/plugins/data`; with none it exits 1 asking for `CLAUDE_PLUGIN_DATA`. It never creates a dir there.
- **The Skill hook fails closed** (`onFailure: block`, and the shim blocks on an engine crash or tamper and asks when the engine can't run), so a broken engine blocks the Skill tool until fixed.

### Changes

- **The CLI uses the hooks' data directory.** `safe-ai-skill allow`, `mode`, `status` and the other commands now find state where the hooks keep it: `CLAUDE_PLUGIN_DATA`, else the `safe-ai-skill-*` directory under `~/.claude/plugins/data` (or `$CLAUDE_CONFIG_DIR/plugins/data`). The `~/.safe-ai-skill` and `./.safe-ai-skill` fallbacks are gone; state written there by 1.0.x was never read by the hooks.
- **New hooks:** PreToolUse `Skill` (`onFailure: block`), `UserPromptExpansion` and a second UserPromptSubmit entry (typed `/name`), PostToolUse `pending-notice` on Bash, the `Write|Edit|MultiEdit|NotebookEdit` tamper tripwire, and SessionStart on `clear` and `compact`. All but the Solana CLI entries and `Skill` fail open (`onFailure: continue`).
- **Bash commands are parsed like a shell parses them.** `gate-bash` splits on newlines, `;`, `&`, `&&`, `||` and `|` outside quotes, strips `FOO=1` prefixes and wrappers (`env`, `sudo`, `nohup`, `time`, `command`, `exec`, `xargs`, zsh `noglob`/`nocorrect`/`repeat`/`=cmd`, …), and follows `$(…)`, backticks, `(…)`, `bash -c '…'`, `eval`, here-documents fed to a shell and launchers such as `find -exec`, `watch`, `tmux`, `nix-shell --run` and `sandbox-exec`. A shell expansion that could turn into flags or extra arguments (`$X`, `$(…)`, `*`) makes a transfer ask instead of allow. (#13)
- **Solana commands are gated however they are spelled.** The always-on Bash hook leaves to the `if`-filtered `gate-bash` only commands whose every `solana`, `spl-token` or `anchor` command is spelled exactly that way at top level. Any other solana command it finds, behind a wrapper, in a script string, after a pipe, in any case, as a path or `.exe`, gets the gate's own decision, resolved and relaxable exactly as in `gate-bash`. A solana name inside code the parser can't read (`bash -c "solana $X"`, `eval`, `python -c`, a pipe into `sh`, unparseable text) or a program spelled as an expansion asks as a hard guard, as does a value-moving solana command written to a script that is then run. A path-qualified program inside such code (`./solana`, `~/.local/share/solana/…/bin/solana`) counts. So does a script written to a file by `echo`, `printf` (with its `%s` arguments filled in), or a here-document or here-string fed to `cat` or `tee`. It counts when that script runs a value-moving solana command, or runs an expansion that may be one (`X=solana; $X transfer …`), and the same command line then runs a file or stdin (`… > x.sh; cat x.sh | bash`). Command output written to a file (`grep solana … > f`, `anchor build | tee log`) and prose (`echo "anchor build failed" > notes.md`) don't count. An expansion run as a program asks only when it could spell a solana program (`$(echo sol)ana`, `X=solana; $X`) or is followed by a solana verb (`$X transfer`), so `$EDITOR close-notes.md` gets no opinion. Mentions in data arguments (`git commit -m`, `grep` patterns, `echo` text) get no opinion. A gate that crashes answers `ask`. **Known limitations:** writing a script in one Bash call and running it in a later one isn't linked, because the second call's `bash x.sh` reveals nothing to parse. Script text the command line doesn't spell out, such as `base64 -d <<< … > x.sh` or a `curl` download, isn't seen either. (#13)
- **Network resolution follows the CLI.** `-C/--config <file>` is read for its `json_rpc_url`. `solana` and `spl-token` use the CLI config, and only `anchor` reads `Anchor.toml` (the nearest one, in any of its `provider.cluster` forms; unreadable or unparseable is unknown). `ANCHOR_PROVIDER_URL` can only make an anchor command riskier. Only exact hosts count as devnet, testnet or localnet (`devnet.attacker.example` is unknown). `solana config get` is given 2 s, after which the network counts as unknown, and its cache is an authenticated state file invalidated by `solana config set`. Policy `network.mainnet: deny` now denies mainnet transfers, deploys and other mainnet asks. (#13)
- **Amounts are plain decimals.** `1e3`, `0x10`, `+1`, `inf` and overlong amounts ask instead of being parsed. (#13)
- **Every PreToolUse gate answers within 8 s.** A gate still running at 8 s, or one that crashes, emits `ask` (a deny it already reached stays a deny). `SAFE_AI_SKILL_DEADLINE_MS` can shorten the deadline to no less than 2 s, never lengthen it.
- **Relaxations need your confirmation in the prompt.** `safe-ai-skill allow` and a tier lowering (`safe-ai-skill tier`, or `--env-read` loosening) only record a request and print its id, never a code. Claude Code shows you the 8-digit code in a hook `systemMessage` (a new PostToolUse `pending-notice` hook on Bash, or at your next prompt or session start), never in the agent's context, and only a hash of it is stored. The request takes effect when your next prompt is exactly `safe-ai-skill confirm <code>`, on its own, within 10 minutes of the code being shown; it works once, and Claude Code then shows what you approved. The code is read only from your prompt; a confirm line inside pasted text is refused; three wrong codes cancel every pending request and are audited as tampering. In headless `claude -p` hook messages aren't shown, so nothing can be confirmed there. Raising the tier and `revoke` apply at once. A grant's clock starts when you confirm it. Residual: code running as you outside the Claude Code sandbox can still run the hook commands itself or nest a `claude -p` session; the tripwire hook blocks the direct forms, and the sandbox is the hard boundary.
- **Grants, the tier, spend ledger and session metadata are authenticated** (HMAC under a per-install key in the plugin data directory) and carry a generation recorded in an authenticated index, so an older valid copy put back is rejected too (restoring a snapshot of the whole directory is not detected). A hand-edited or plain `grants.json`/`mode.json` relaxes nothing. A deleted or edited `spend.json` counts as today's budget spent, so within-cap devnet transfers ask until the next UTC day; a 1.0 upgrade starts that way too. Grant debits are serialized, so parallel calls can't overspend a grant. Grants and mode apply only when the data directory is in a trusted location (under `~/.claude/plugins/data`, outside the project). Tamper-evident, not tamper-proof: anything running as you can read the key.
- **1.0 state is converted once, never into live relaxation.** At the first 1.1.0 SessionStart, each unexpired 1.0 grant (valid scope and addresses) becomes a pending request whose code that SessionStart shows you; you keep what you confirm. Profiles map onto tiers (`paranoid` to `high` immediately, `strict` and `autopilot` to `relaxed`). The 1.0 `spend.json` becomes an exhausted ledger for today. Unreadable files and the removed `off` mode are set aside as `*.v1-unmigrated`. An authenticated `migrated.json` marker stops a second run; even a staged one (key, marker and envelopes deleted) yields only requests you must confirm.
- **Grant scopes are checked.** `--scope` must be `transfer`, `swap`, `deploy`, `authority` or `destructive`; anything else, including the removed catch-all `other`, is an error (exit 1). `--programs`/`--to` take base58 addresses only, and a grant runs at most 30 days.
- **Profiles are replaced by tiers** (see Behaviour changes). The `off` profile is gone as a profile: the tier `off` keeps every deny row. The never-read `relax_transfer`, `relax_swap`, `disabled`, `gates` and `hard_guards` settings, `profiles:`, `ask_all` and the autopilot cap are removed; a policy that still has them loads, and SessionStart lists them as ignored. To turn the hooks off, use `SAFE_AI_SKILL_DISABLE=1`.
- **SessionStart and `status` print `tier: <t> (<source>); sandbox: <state>`, and SessionStart lists active loosenings:** a tier below the default, live grants, ignored tier hints, ignored repo policy, state that failed authentication, items migrated from 1.0, and (alongside any of those, or when settings turn it off) a Claude Code sandbox that is off. A clean session prints nothing.
- **Secret paths are matched by class, case-insensitively, on the raw and the symlink-resolved path.** `.ENV`, `.envrc`, `*.env`, `.dev.vars`, `C:\p\.env`, `.env::$DATA` and symlinks to `.env` are now env files; a file whose content is a keypair or a private key is denied under any name; `id.json` and `*.pem`/`*.key` are denied only when they hold (or can't be checked for) key material, so ordinary `id.json` data files and certificates are readable. Default `deny_read_globs` shrank to the extras, and `.env.sample|.template|.dist|.schema` joined `allow_read_globs`. (#7)
- **Env-file denies name the way out.** The message gives `safe-ai-skill env keys|set|unset` for the file, plus `varlock load --agent` / `varlock run -- <cmd>` when the project has a `.env.schema` or varlock is installed. `secrets.env_read: ask` (plugin policy only) restores prompted raw reads. (#7, #14)
- **Grep and MCP are gated on paths.** Grep is judged on `path` and `glob`, never its regex; a directory Grep gets env and key files excluded through `updatedInput` (no permission decision). Glob is not gated. MCP calls get the read check on every path-like string argument (`ctx_execute_file {path:".env"}` → deny). (#7)
- **Bash secret nudges cover more readers.** `source`, `.`, `grep`, `sed`, `awk`, `nl`, `tac`, `< file` redirects, `git show REV:.env`, and commands behind `sudo`/`env`/`VAR=…` prefixes. varlock commands that print resolved values are denied like `cat .env`; `varlock run --no-redact-stdout` asks. (#7, #14)
- **The redact hook works.** It read `tool_output` and answered with a top-level key, so it never changed anything. It now reads `tool_response`, answers with `hookSpecificOutput.updatedToolOutput` in the tool's own shape (Read, Bash, Grep, MCP), runs on MCP output too, replaces literal values from the project's env files with `«redacted:KEY»`, and scans payloads up to 8 MiB (larger ones pass unchanged). (#7)
- **New:** `safe-ai-skill env init-schema [FILE]` writes a `.env.schema` from an env file's keys (no values, never overwrites); `env keys` annotates keys from a `.env.schema` beside the file; `safe-ai-skill doctor` checks the Claude Code sandbox settings; a one-time SessionStart tip suggests a schema when a project has env files without one. (#14)
- **The shim checks the engine binary's sha256.** Each release stamps the prebuilts' sha256 into the shim. A binary that doesn't match is treated as tampered and never runs: `gate-bash`, `gate-mcp` and `gate-skill` block, the other PreToolUse gates ask, SessionStart reports the firewall TAMPERED and CLI commands exit 2. A locally built engine copied into `bin/` must be stamped with `scripts/stamp-shim.sh`. If neither `sha256sum` nor `shasum` exists, the shim fails open with a notice like any other environment failure (`SAFE_AI_SKILL_STRICT=1` blocks).
- **Windows (Git Bash) is supported.** Releases ship `safe-ai-skill-windows-x64.exe`, statically linked against the C runtime; Windows on ARM runs it under emulation. The shell gates cover the `Bash` tool only, and SessionStart says so: `PowerShell` tool calls are not gated, and PowerShell-only Windows fails open with a notice. `install.sh` and the npm package install the Windows binary too.
- **SessionStart warns about a duplicate install** (more than one `safe-ai-skill@*` in `~/.claude/plugins/installed_plugins.json`: Claude Code runs only one copy's hooks) **and about Claude Code older than 2.1.295.** The version is read from `CLAUDE_CODE_VERSION`, else from the version in `CLAUDE_CODE_EXECPATH`; when neither gives one there is no warning (no `claude --version` per session).
- **Shim hardening.** The engine's output is captured in memory and never written to a file. A Linux binary for the wrong ELF class or machine is an environment failure, not an exec attempt. `SAFE_AI_SKILL_DISABLE` is ignored when the committed `.claude/settings.json` contains any `SAFE_AI_SKILL` text or any `\u` escape (a JSON-escaped key), and when the session check exits 2 or 3 the ignored-DISABLE notice goes to stderr (the exit status stands).

- **Supply-chain state v2 (#10, #12).** Per-pack state (`state.json`, authenticated) keyed by path: `clean`, `warned` (documentation findings), `unreviewed` (a first-seen code HIGH: warned, not denied) and `blocked` (a combination rule, drift, or a mismatch with a committed `.safe-ai-skill/packs.lock`). 1.0 lockfile pins are carried over. `verify approve <name|dir>` and `verify trust <dir>` only create pending requests confirmed like grants; approval and trust are bound to the content shown and never clear a combination rule. Worktrees and clones reuse trust by content hash. The Skill tool and typed `/name` commands are checked against the packs that provide the name, re-hashing a pack whose stat fingerprint changed.
- **Rule-based pack scanner (#10).** Detectors with code/doc/meta context replace the line heuristics: findings in docs cap at WARN, a single code signal is HIGH, and only combinations (`bang_exfil`, `padding_sink`, `eval_decoder`, `symlink_escape`, `lifecycle_network`, `description_injection`, …) BLOCK. Each pack's scan has a time allowance within the sweep's; a cut scan is recorded unscanned (denied) and rescanned next session. Coverage, limits and the comparison with external scanners: `docs/scanner-coverage.md`.
- **Tamper tripwire, 1.1.0 rules.** The agent may run `allow` and `tier` (a grant or a lowering only creates a request); Bash invocations of `confirm`, `revoke`, `verify approve|trust`, `install`, `add`, bare `verify` / `verify session` and every hook subcommand (`prompt-guard`, `pending-notice`, `redact`, `gate-*`) are denied. A nested Claude Code session (`claude -p`, `npx @anthropic-ai/claude-code`) that mentions `safe-ai-skill confirm` is denied, and any other non-interactive one asks. `pending.json`, `generations.json`, `migrated.json`, `sessions.json` and the lock files are protected state.
- **`safe-ai-skill doctor`** also recommends sandbox `denyRead` for `~/.claude/projects/**` and the data dir's `key`.

### Known limitations in 1.1.0

- **The firewall is hook-level string analysis and has known holes.** README and SECURITY.md carry the list. The solana-ai-kit sandbox and permission rules (or Claude Code's own sandbox with the recommended `denyRead`/`deniedDomains`) close most of them; run both.
- Bash writes to a project `.env` (`sed -i`, `perl -pi`, `python3 -c`) are not covered at any tier.
- The exfil tripwire does not stop raw IP literals, redirects, DNS, unlisted hosts, `WebFetch`/`WebSearch` URLs or values already in context.
- A script written in one Bash call and run in a later one is not linked; script text built by encoding or indirection (`base64 -d`, `$'…'`, variables) is seen only where the parser can read it.
- Reads of `~/.claude/projects/**` are denied (deliberate), which also stops the agent reading its own auto-memory files with its tools.
- A localhost RPC proxy that forwards to mainnet counts as an identified localnet.
- The sandbox state is declared configuration, not a runtime proof, and the kit's `excludedCommands` run unsandboxed.
- A dev tunnel to your own ngrok host (or any host on the exfil list) is denied from Relaxed; `exfil_hosts_extra` can't remove it, a user-scope `off` tier can.

### Documentation

- README and SECURITY.md open with a disclaimer: what the plugin cannot protect on its own, which holes the kit's sandbox and permission rules close, and the recommended setup. `docs/tiers.md` explains the tiers, selection and confirmation, the sandbox-conditioned `.env` opt-in, migration, the shared lists and the headless rule. `docs/drafts/aikit-firewall-split.md` drafts the proposed kit-side changes ([ai-kit#264](https://github.com/solanabr/ai-kit/issues/264), [ai-kit#265](https://github.com/solanabr/ai-kit/issues/265)); nothing in it is posted.

### Release process

- The build and attest jobs are split: only the attest job holds `id-token`/`attestations` write, checks out nothing, and runs two actions pinned by commit SHA. The vendor job stamps the shim with the binaries' sha256 before regenerating `SHA256SUMS`.
- The musl and Windows binaries are built twice from clean and must be byte-identical; every build remaps the workspace and cargo home paths.
- Releases are built, attested and vendored on the protected `release/vX.Y.Z` branch (as in 1.0.1); the vendor job also stamps the shim, and publish checks the stamped shim and that every committed binary is the tagged version.
- CI checks the shim's stamped constants (and verifies the Windows binary's attestation too); runs a `windows-latest` build and engine tests; and enforces the latency budget (cold `gate-read` through the shim under 50 ms on musl, the SessionStart sweep at most 2x the shipped binary's).

## [1.0.1] — Unreleased

### Summary

Security hotfix for #5–#13. Several defaults change; each change is listed below. Design and evidence: `docs/superpowers/specs/2026-10-21-open-issues-design.md`.

### Behaviour changes

- **No opinion means no output.** A gate with nothing to say prints nothing and exits 0. 1.0.0 printed `defer` on every benign call, and `defer` stops the tool call under `claude -p`. Unknown subcommands exit 3, and `--version` prints the version. (#13)
- **Skill packs are reported, not quarantined.** SessionStart findings and pin drift are reported in the session, and a drifted pack is reported every session until you run `verify approve <name>`, which re-pins it in place. Nothing is moved, so `git status` stays clean, and a clean sweep prints nothing. `~/.claude/skills` is scanned only when a project's `.safe-ai-skill/policy.yaml` adds it to `supply_chain.verify_skills_dirs` (the only dir outside the project a project may add), except for packs installed there with `install --from`. `verify approve` still restores packs that 1.0.0 moved into `quarantine/`, and never overwrites an existing directory. (#5, #9)
- **Unsupported platforms fail open with a notice; Solana commands still ask.** If the engine can't run (no binary for the platform, exit 126/127, a broken interpreter), hooks exit 0 with one stderr line and SessionStart reports the firewall INACTIVE, while `solana`, `spl-token` and `anchor` commands get `ask`. `SAFE_AI_SKILL_STRICT=1` blocks instead, and `SAFE_AI_SKILL_DISABLE=1` switches the hooks off, unless strict mode is set or the project's committed `.claude/settings.json` mentions it or can't be read (a repo can't disable the firewall). An engine crash still blocks `gate-bash` and `gate-mcp`. The shim no longer falls back to `cargo build` or runs a binary from the plugin data directory. (#6)
- **Irreversible flags and unknown networks ask.** `--final` deploys and upgrades, upgrade-authority changes, `program close`, `spl-token authorize … --disable`, `spl-token close|close-mint`, `anchor idl erase-authority|set-authority|close` and `solana close-vote-account` ask on every cluster, and mainnet `--final` is denied. A command whose cluster can't be identified asks instead of passing. Transfer amounts are read from positional arguments only. (#13)
- **The agent can't grant itself permissions.** A tamper tripwire denies agent tool calls that would loosen the firewall from the inside. On Bash, that is running the `safe-ai-skill` binary with a mutating subcommand (`allow`, `grant`, `revoke`, `confirm`, `mode <profile>`, `verify approve|trust`, `install`, `add`, and the hook-only bare `verify` / `verify session`, which pin packs), or a command that references protected state. A new `Write|Edit|MultiEdit|NotebookEdit` hook (`gate-tamper`) denies writes to protected state, with symlinks resolved. Protected state is the plugin data dir (grants, mode, spend ledger, audit log), the legacy `~/.safe-ai-skill` dir, the installed plugin under `plugins/cache/` and its `hooks.json`, and the state files of a project `.safe-ai-skill/` dir; a project's `policy.yaml` stays editable because it can only tighten. Read-only commands (`status`, `verify check`, bare `mode`) pass. A Bash command too large or complex to scan within the tripwire's work budget asks instead of passing, and a Write payload the engine can't read asks. Run grant and mode commands yourself in a terminal. This is a tripwire against a careless or prompt-injected agent, not a sandbox: encoded commands, variable indirection or scripts written now and run later can get past it.
- **The CLI uses the hooks' state.** With `CLAUDE_PLUGIN_DATA` unset (your own terminal), the CLI resolves the plugin's data dir under `$CLAUDE_CONFIG_DIR/plugins/data/` or `~/.claude/plugins/data/`: `safe-ai-skill-safe-ai-skill`, then `safe-ai-skill-stbr`, then the only `safe-ai-skill-*` dir; otherwise it exits 1 and asks for `CLAUDE_PLUGIN_DATA`. 1.0.0 fell back to `~/.safe-ai-skill` (or `./.safe-ai-skill`), so `allow`, `mode` and `verify approve` run from a terminal changed state the hooks never read. State is no longer written there or to the working directory, and `status` prints the dir it used.
- **Repo policy can only tighten.** A project's `.safe-ai-skill/policy.yaml` can lower caps and add checks, but it can no longer raise caps, shrink the scanned skill directories, add a directory outside the project other than `~/.claude/skills`, or change the profile. `SAFE_AI_SKILL_PROFILE` can only select a stricter profile than the one in effect. Ignored keys are listed at SessionStart.
- **The marketplace is named `safe-ai-skill` again.** Install `safe-ai-skill@safe-ai-skill`, as in 1.0.0. If you installed `safe-ai-skill@stbr`, follow the README migration and don't remove `stbr` without checking it first: the solana-ai-kit marketplace has the same name. solana-ai-kit users don't need to do anything. (#8)
- **Linux binaries are static (musl).** 1.0.0's `linux-x64` needed glibc 2.39, so it failed on Ubuntu 22.04 and Debian 12 and the firewall was silently off. File names are unchanged. (#6)
- **varlock `.env.schema` is readable.** `**/.env.schema` joins `**/.env.example` in `secrets.allow_read_globs`, so Read, Grep and `cat` of a schema no longer hit the `.env.*` deny. `.env`, `.env.local`, `.env.<env>`, `.env.schema.local` and `.env.schema.bak` stay denied. A Read (or Grep with a file path) of a schema is still denied when it contains key material (a keypair array, a base58 64-byte secret key, a private-key block, an `sk-`/`sk_live_` token, a JWT, or a literal value on a `*_API_KEY`, `*_SECRET`, `*_TOKEN`, `*PASSWORD*`, `*PRIVATE_KEY` or `*_KEY` line whose name contains SECRET, PRIVATE, AUTH or ACCESS; a trailing `# comment` is ignored; empty values, placeholders, `$VAR` and function calls such as `varlock(...)` pass), and when it is over 64 KiB, unreadable, not a regular file, or a symlink to a non-schema file. Known limits: Bash `cat .env.schema` and Grep with a directory plus glob get no content check; output redaction is not active in 1.0.1. A repo that lists only `**/.env.example` removes the schema allow, because repo allow-lists intersect with the base. safe-ai-skill does not run or parse varlock. (#14)
- **Claude Code 2.1.295 or newer is required** for the hooks' `onFailure` setting. Older versions still run the hooks, but a hook that can't start never blocks.

### Known limitations in 1.0.1 (fixed in 1.1.0)

- Output redaction is not active in 1.0.1 (fixed in 1.1.0).
- Swap risk scoring (rugcheck) and Squads routing are not wired; MCP swaps always ask.
- A directory-wide Grep can still return `.env*` contents. Until 1.1.0, rely on Read-level protection and the Claude Code sandbox `denyRead`.
- A Solana command wrapped in another command or prefixed with environment assignments may not be gated. Keep the sandbox on.
- There is no SessionStart notice yet for Claude Code older than 2.1.295.
- Deleting a parent of the plugin data directory (for example `~/.claude/plugins/data`) resets the daily spend ledger, along with grants and pins. The tripwire doesn't cover removing an ancestor. 1.1.0 fixes this with authenticated state.

### Documentation

- README, SECURITY.md and ARCHITECTURE.md describe report-only drift, the fail-open shim, the self-grant tripwire and the threat model (a careless or prompt-injected agent; the Claude Code sandbox is the hard boundary). The README no longer lists `install --from <url|ref>`: only a local directory or tarball is supported. It also lists the real `allow` syntax and the profiles `strict`, `autopilot`, `paranoid` and `off`, and drops `pin-mcps`, which doesn't exist.

### Release process

- Release tags now point at a commit that contains the binaries. `v1.0.0` predates the commit that vendored its binaries (a8d20f8), so anything that resolved the tag got a plugin without them. `release.yml` now builds on manual dispatch from the protected branch `release/vX.Y.Z` only, attests each binary's build provenance and commits the binaries to that branch. The maintainer tags that commit `vX.Y.Z` and `safe-ai-skill--vX.Y.Z` (the form plugin dependency version ranges resolve) and merges the branch to `main`, so `main` gets new hooks and the binaries they call in one merge. The tag push publishes the GitHub Release from the committed binaries once they report the tagged version, their checksums check out and their attestations prove they were built by `release.yml` on `release/vX.Y.Z`. Steps, including the one-off `safe-ai-skill--v1.0.0` tag on a8d20f8, are in `docs/RELEASING.md`.
- Release builds use a pinned toolchain (1.98.1, the same pin as CI), `--locked`, explicit macOS minimums (11.0 on arm64, 10.12 on x64), no build cache and no third-party actions. The unused cosign stub is gone.
- CI builds the musl binaries, checks that they're static and run on alpine, debian:11 and ubuntu:20.04, verifies the provenance attestation of every committed binary, and fails when a committed binary isn't the version in `plugin.json` (`scripts/check-binary-versions.sh`; it runs the native binary and finds the version line in the others). That check keeps a version bump off `main` until its binaries are vendored. The npm e2e also runs in alpine and Debian 11 containers on x64 and arm64, and `release.yml` runs it after each publish.
- `scripts/check-versions.sh` also checks `Cargo.lock` and `install.sh`, and accepts an expected version.

## [1.0.0] — 2026-06-26

### Summary

First stable release. Ships the safe-ai-skill engine, runtime action firewall, and supply-chain verifier as a standalone, general-purpose Claude Code plugin — it secures any skills, MCPs, and agents. `solanabr/solana-ai-kit` v2.0.0 is the reference integration used to exercise and document the gates, not a requirement.

### Engine

- Static Rust binary (`safe-ai-skill` / `safe-ai-skill`) with synchronous I/O; no runtime dependency. Prebuilt for `darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64` with `SHA256SUMS`. Falls back to `cargo build --release` if no prebuilt matches; shim exits code 2 (block) if neither path is available — never fails open.
- Hook wiring: `gate-bash` (solana/spl-token/anchor CLI), `gate-bash-secrets` (unconditional secret and exfiltration patterns), `gate-read` (secret file globs), `gate-mcp` (value-moving MCP tools), `redact` (PostToolUse secret scrub), `prompt-guard` (UserPromptSubmit private key/seed block).
- Append-only audit log (`audit.jsonl`), TOFU lockfile (`lockfile.json`), daily spend ledger (`spend.json`), time-boxed grant store (`grants.json`), session keypair dir (mode 0600).
- Policy DSL (`default.policy.yaml`): full schema synced on-disk including `catalog`, `ext`, and `exec_install_scripts` fields. Deep-merge over project `.safe-ai-skill/policy.yaml`. Fail-closed on parse error.
- Four profiles: `strict` (default), `autopilot`, `paranoid`, `off`. Profiles adjust soft-gate thresholds; hard guards are unaffected by all profiles, grants, and flags.
- Hard guards (`mainnet_deploy`, `set_authority`, `account_close`, `secret_read`) enforced unconditionally — not present in the policy DSL, not relaxable by any configuration.

### Runtime firewall

- `gate-bash` classifies commands into `transfer`, `deploy`, `authority`, `destructive`, `install_script`, `readonly`. Mainnet + non-readonly → `ask`. Spend caps → allow/ask/deny. `install_script` (curl/wget piped to bash/sh) → `exec_install_scripts` policy value (`allow|ask|deny`; default `ask`).
- `gate-mcp` sensitive name pattern extended to cover `stake|delegate|mint|bridge|lend|borrow` in addition to the prior `transfer|sign|swap|send|withdraw|burn|pay|upgrade` — catches `heliusWrite.stakeSOL`, `heliusWrite.delegateStake`, and equivalent staking/DeFi verbs from solana-ai-kit's `heliusWrite` MCP.
- `gate-mcp` enforces catalog risk classes at runtime: tools from `wallet_signing` entries show a risk-class header on every approval prompt; `key_custody` entries are gated independently of name-pattern matching.
- Rugcheck swap gate: mint score above `rugcheck_max_score` (default 40) → `deny`; API timeout → `ask` (never allow).
- `deny` verified to survive both `bypassPermissions` and `enableAllProjectMcpServers: true` (Claude Code hook execution order).
- Supersedes the solana-ai-kit mainnet-deploy hook, which uses `read -r` in hook context (no TTY — silently fails open).

### Supply-chain verifier

- `install` subcommand: hub-agnostic secure install flow. Accepts `--from <url|ref>` and `--home <dir>`. Runs verification pipeline, shows diff of all flagged content, prompts for approval before writing. Does not auto-widen `~/.claude/settings.json` permissions. Replaces the retired `bootstrap` subcommand (which was hard-coded to a remote `skills.tar.gz` tarball and is no longer applicable).
- Per-`ext`-submodule verification (`ext_verify.rs`): each of solana-ai-kit's 18 `ext/` git submodules is walked independently at `SessionStart`. Git SHA pinned on first seen (TOFU). SHA drift triggers quarantine + diff in `additionalContext` + `reloadSkills: true`. `safe-ai-skill verify approve ext/<name>` re-pins after user review.
- `registry.rs`: parses `skill-registry.json` (39 opt-in entries, `default_installed: false`). Classifies entries by risk class (`wallet_signing`, `key_custody`, `installer_script`, `standard`). High-risk classes gate installation and runtime tool invocation per policy.
- `registry list` and `registry verify` subcommands: list catalog with risk classes and install status; audit installed entries against pinned catalog state.
- `add skill <name>` resolves catalog entries, checks risk class against policy before running verification pipeline. High-risk entries show risk summary; denied classes refuse install.
- `add mcp <id>` resolves catalog MCP entries, pins to exact `pkg@version` + `dist.shasum`, writes to `.mcp.json`. `@latest` entries in existing `.mcp.json` are flagged INFORMATIONAL — not auto-rewritten. `safe-ai-skill pin-mcps` offered as opt-in rewrite.
- Static heuristics (`heuristics.rs`): telemetry curl patterns, `curl|bash` installer patterns, keypair references, prompt injection markers (Unicode bidi, hidden comments), unpinned npx. All patterns are generic; no package-specific allowlists to maintain.
- osv.dev CVE lookup for all resolved `pkg@version` entries. No auth required.
- Every `ext/` submodule treated identically — telemetry preambles flagged and neutralized generically by `heuristics.rs`. No special-casing; known supply-chain risks are addressed through the generic per-submodule pipeline, not custom code.

### MCP posture

- solana-ai-kit ships all 7 MCP servers at `@latest`. safe-ai-skill flags these INFORMATIONAL (LOW) at `install` time and `SessionStart` by design — the kit's `@latest` posture is intentional, and safe-ai-skill does not nag or auto-pin. Runtime gating by tool name and payload operates independently of pin status.

### Relaxation model

- Time-boxed grants (`safe-ai-skill allow`): relax soft gates for a bounded scope and duration. Stored in `grants.json`; expire automatically. `safe-ai-skill revoke` cancels early.
- Hard guards bypass no grant, profile, or flag in v1. This is an engine property, not a default.

### Distribution

- **Plugin** (always-on firewall): `claude plugin marketplace add solanabr/safe-ai-skill` → `claude plugin install safe-ai-skill@safe-ai-skill`. Ships committed platform binaries; the shim resolves the native prebuilt, else builds from `crates/engine`, else fails closed.
- **CLI** (`safe-ai-skill` Tier 1/2 commands) via three paths, all checksum-verified against the release `SHA256SUMS`:
  - npm — `npm install -g @stbr/safe-ai-skill` / `npx @stbr/safe-ai-skill` (CLI command: `safe-ai-skill`). `postinstall.js` downloads the platform binary from the matching GitHub Release tag and aborts on checksum mismatch (no silent install).
  - Standalone — `curl -fsSL …/install.sh | sh`. Downloads + verifies the binary before installing to `~/.local/bin` (overridable via `SAFE_AI_SKILL_BIN_DIR`); fails loud, installs nothing on mismatch.
  - cargo — `cargo install safe-ai-skill` (builds from source on any Rust-capable platform).
- README Install section separates the always-on plugin (firewall) from the `safe-ai-skill` CLI.

### Tooling & CI

- `release.yml` builds all four platform binaries (`darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64`) and regenerates `SHA256SUMS` on every `v*` tag.
- `ci.yml`: lint (fmt + clippy), native build+test matrix with an npm-launcher smoke, a build-only cross-build job covering `darwin-x64` + `linux-arm64`, committed-binary checksum verification, and a `package-checks` job (`node --check` on the npm wrapper, `shellcheck`/`sh -n` on shell scripts, and `scripts/check-versions.sh` asserting npm/Cargo/plugin/marketplace/README versions agree).
- `npm-e2e.yml` (release/schedule/dispatch): packs, installs, checksum-verifies, and execs the published CLI end to end.
- Repo hygiene: `.claude/` (local dogfooding config) is gitignored and the shipped plugin lives in `plugins/`; `.DS_Store`, OS/editor clutter, and install-time-downloaded `npm/bin/safe-ai-skill-*` binaries are ignored.
- Folding safe-ai-skill into the `stbr` solana-ai-kit marketplace is deferred to a future release.

- Turnkey SaaS wallet integration (skipped in favor of session keypairs).
